## Architecture

Single-screen React + TypeScript + Vite + Tailwind 4 app. No router.

**Layers:**

- `src/services/firebase.ts` — Firebase app init, exports `db`
- `src/services/auth.ts` — `useAuth()` hook, `signIn()` (Google popup)
- `src/data/store.ts` — `Store` interface + shared `CACHE_KEY`
- `src/data/local-store.ts` — `Store` impl backed by localStorage (dev only)
- `src/data/remote-store.ts` — `Store` impl backed by Firestore with localStorage read-through cache (prod)
- `src/main.tsx` — composition root: picks `localStore` or `remoteStore` based on `import.meta.env.DEV`, injects into `<App store={store} />`
- `src/App.tsx` — receives `store: Store` as a prop; no env branching inside

**Dev vs prod:**

- Dev: auth is bypassed with a fake user; all reads/writes go to localStorage only — no Firebase calls
- Prod: Google auth required; reads are cache-first (localStorage), writes go to Firestore and update the cache

**Environment variables:**

- `VITE_FIREBASE_API_KEY` — the only secret; all other Firebase config is hardcoded in `src/services/firebase.ts`

**Deployment:** builds to `docs/`, served from GitHub Pages at `/fuel/`. CI runs on push to `main` via `.github/workflows/deploy.yml` — requires `VITE_FIREBASE_API_KEY` set as a GitHub Actions secret.

## Data model

`src/types/fillup.ts` — all fields except `id` and `date` are optional since the spreadsheet has many partial entries.

```ts
{ id, year, month, day, totalCost?, liters?, tripKm?, odometer?, estimated? }
```

Firestore document IDs are used as `id`; generated by Firestore on `addDoc`. In dev, IDs are generated client-side as `${Date.now()}-${random}`.
